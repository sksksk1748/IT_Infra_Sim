# 萬人網管 InfraOps

一款 **IT 基礎架構工程師模擬遊戲**：新曜集團的一萬名員工即將遷入 23 層的新總部（地下還有 B2 員工停車場），而你手上只有一間空蕩蕩的 B1 機房。從機櫃、路由器、防火牆、核心交換器，到每層樓的布線、Wi-Fi、跨樓層光纖主幹，親手打造整間公司的網路；再往外把台中、高雄、越南、東京四個據點與雲端連回總部，往內整頓虛擬化、儲存、備份、電話系統與一萬台電腦，並在流量高峰、設備故障與駭客攻擊中守住它。

純 HTML / CSS / JavaScript，**不需要安裝任何東西**。（3D 設備模型使用 [Three.js](https://threejs.org/) r128，第一次打開 3D 畫面時才從 cdnjs 載入，需要網路連線；離線時其他功能照常運作。）

**▶ 線上遊玩：https://sksksk1748.github.io/IT_Infra_Sim/**

## 怎麼玩

### 直接開啟
雙擊 `index.html`，用 Chrome / Edge / Firefox 開啟即可。

### 本機伺服器（選用）
這台電腦沒有 Node / Python 也沒關係，專案附了一個 PowerShell 小伺服器：

```bash
powershell -ExecutionPolicy Bypass -File tools/serve.ps1 -Port 8080
```

然後打開 http://localhost:8080/ 。

### 遊戲模式
- **劇情模式**：九個章節，任務面板會一步步引導你；不知道下一步要做什麼時，有提示會用黃色邊框標出要點的地方（見下方「提示」）。
- **沙盒模式**：預算 1.5 億、全部設備解鎖，員工在第 3～6 天分批進駐全部樓層（B2 員工停車場第 3 天一早啟用，22F、23F 員工餐廳同時開張），第 5～7 天四個分支據點陸續開幕，週一起客服中心要換成 IP 電話交換機，隨機事件照常發生。
- **情境挑戰**：開始畫面的「情境挑戰」。每個情境都會先蓋好一套公司網路（刻意留一些弱點），把時間撥到事發前，限時處理完畢後依結果評分（S / A / B / C / D）並給出檢討，最佳成績記在這台瀏覽器：
  - **凌晨 3 點：勒索軟體**（困難）：6F 爆發勒索軟體，09:00 上班前完成遏制、根除、復原。
  - **季末流量高峰**（中等）：找出路由器、防火牆、專線哪個是瓶頸，預算內升級，撐過 3 小時的 1.6 倍流量。
  - **官網上線日：DDoS**（中等）：發表會流量 3 倍、DDoS 與 SQL Injection 接連來襲；容量規劃、上游清洗、WAF 缺一不可。
- **章節小測驗**：每章 5～6 題選擇題（知識庫右上角「章節小測驗」，或完成章節時直接開始）。答錯會附上解說與相關知識卡，劇情模式只開放已經玩到的章節。

### 操作
- 上方 `❚❚ 1× 5× 20× 60×` 控制時間，`⏭` 快轉到早上；鍵盤 `0`～`4` 切換速度、空白鍵暫停 / 繼續。
- 左側（手機在下方）是一排「交換器連接埠」導覽，亮琥珀燈代表那裡有事情需要處理。
- 進度每遊戲小時自動存在瀏覽器；「選單」可以匯出 / 匯入存檔文字。
- **雲端存檔**：「選單 → 雲端存檔」（或開始畫面）用 Google 帳號登入，每個帳號有 3 格雲端存檔，換電腦或手機也能接著玩（詳見下方「雲端存檔」）。
- **淺色 / 深色背景**：右上角的 ☀ / ☾ 按鈕可以一鍵切換；「選單 → 畫面外觀」與開始畫面可選「跟隨系統 / 淺色 / 深色」，選擇會記在這個瀏覽器（手機版請從選單切換）。

### 提示
每個任務都拆成一步一步。任務面板的「💡 下一步」會告訴你現在要做什麼：
- **帶我去**：直接跳到那一頁，要點的按鈕、分頁、平面圖或拓撲上的設備會**閃黃色邊框**，旁邊的黃色泡泡寫著要做什麼；做完一步，下一步會自動標出來（引導模式）。
- **卡住時自動提示**：同一步停超過 25 秒，提示會自己亮起來。
- **緊急狀況優先**：有嚴重事件、整層斷線或機房過熱時，提示會先帶你去處理。
- **滿意度上不去**：提示會自動診斷原因——路由器 / 防火牆滿載就引導你換大一點的型號（買 → 上架 → 賣掉舊的 → 重新接線），頻寬不夠就加專線，其他問題就帶你去看報修。
- 沙盒模式也有「建議下一步」。「選單 → 提示」可以改成「點了才提示」或關閉；點提示泡泡可以先關掉。

### 雲端存檔
- **怎麼用**：「選單 → 雲端存檔」用 Google 帳號登入。選一格「上傳目前進度」後，這一局就連結到那一格，之後每 5 分鐘（有新進度時）、章節開始與完成、離開頁面時自動上傳；在別台裝置登入同一個帳號，按「讀取」就能接著玩。
- **不會蓋錯**：每一局遊戲有自己的識別碼。欄位裡存的是另一局、或雲端的進度比這台新（在別台玩過）時，自動同步會暫停並提醒，不會覆蓋；手動覆寫前也會再確認。
- **存了什麼**：只有遊戲進度（gzip 壓縮後約 5～30 KB）和摘要（模式、章節、遊戲時間、預算、員工數）。Google 帳號只用來辨識是誰的存檔；每個玩家只能讀寫自己的資料（Firestore 規則見 `firestore.rules`）。
- 本機存檔仍然是主要存檔：沒登入、離線或直接開啟 `index.html` 時照常可以玩（雲端功能要從網址開啟）。
- **自己架設**：在 Firebase 建立專案 → 新增網頁應用程式 → Authentication 啟用 Google 登入並把網站網域加到「授權網域」→ 建立 Firestore（正式版模式）並貼上 `firestore.rules` → 把 `firebaseConfig` 填進 `js/core/cloud-config.js`。留 `null` 就不會出現雲端存檔功能。

已經破關的舊存檔，任務面板會出現「新章節開放」，可以直接接著玩後面的章節。

### 第九章「割接之夜」怎麼玩
1. **準備（上班時間，不花窗口時間）**：打開割接計畫書（MOP）；新核心是原廠出廠設定——**STP 預設關閉**，還留著一條把兩個埠接在一起的**燒機測試線**（新核心一接上網路就會引發全公司的廣播風暴）；舊核心上六成的線**沒有標籤**，要逐條循線貼好；依 MOP 在新核心插好和對端**同一種的光模組**；新核心和另一台核心之間接兩條 100G 並設定 **LACP**（廠商附的新跳線裡有一條極性是反的，不通就翻轉）。
2. **維護窗口（凌晨 02:00 自動暫停）**：時間只在你動手時前進——拔線、插線、插模組各 1 分鐘、循線追蹤 6 分鐘、改設定 2 分鐘。一次搬一條：在舊核心「拔掉這一端」→ 拿著懸空的那一端插到新核心 MOP 指定的埠 → 燈號轉綠再搬下一條。新核心裝在別座機櫃時，同機櫃用的 3 m 跳線拉不過去，要換一條 12 m 的新跳線。
3. **驗證與下架**：所有樓層與服務正常 30 分鐘後，拆掉舊核心剩下的互連線、下架。
4. **成績單（S～D）**：窗口內影響的人分鐘、接錯 / 不通的次數、廣播風暴、沒到窗口就動線（違反變更管理）、超過窗口的時間、窗口開始時還沒標籤的線。先搬雙上行的樓層、單線的設備放最後，就能做到零影響。

## 遊戲中對應的真實概念

| 你要求的主題 | 在遊戲中怎麼體驗 |
|---|---|
| Router | 路由效能上限、NAT、單 WAN（主備援）vs BGP（多 ISP 負載分擔） |
| Switch | L2 / L3、埠數與埠速（RJ45 / SFP / QSFP）、接入交換器 PoE 預算、核心埠數用完 |
| Server | 角色（AD、檔案、DB、官網、NMS、SIEM、備份、電話、弱點掃描、更新快取）、網卡速率、放在哪個區域 |
| Rack 架設 | 42U 機櫃逐 U 上架、每櫃 8 kW PDU 上限（超過會跳脫）、UPS、精密空調、機房溫度；B1 機房最多 24 座機櫃，分成兩組冷熱通道 |
| 設備互接（實體接線） | 「機房 → 實體接線」：每個埠插什麼模組、接什麼跳線；SR / LR、LC / MPO、DAC、極性、LACP；多接一條線形成迴圈時 STP 會擋下，沒開 STP 就是廣播風暴；第九章在凌晨的維護窗口把舊核心的線一條條搬到新核心（MOP、標籤、變更管理） |
| 樓層間布線 | 每層樓的水平布線（發包施工，或自己布線：在平面圖上從 IDF 畫走線、避開電力線槽、依 T568B 色序打線、用測試儀驗證接線圖 / 長度 / 串音）、經弱電豎井到 B1 的主幹線；Cat6 / Cat6A / OM4 / OS2 的距離與速率限制、光模組成本、LACP |
| Wi-Fi 與有線 | 平面圖上放 AP、牆壁與電梯井衰減、覆蓋 vs 容量、同頻干擾、WLC 自動頻道；有線座位的埠數 |
| 外網與內網 | 防火牆介面區域（OUTSIDE / INSIDE / DMZ）、依實際接線判定安全區域、繞過防火牆會被健檢抓出來 |
| 流量即時監控 | 監控中心：WAN / 內部流量趨勢、鏈路使用率排行、NetFlow 異常流量、告警；沒有 NMS 就看不到 |
| 防火牆 | 由上而下比對的規則表、預設拒絕、命中數、遮蔽規則偵測、業務必要連線檢查、資安健檢評分 |
| 駭客攻擊 | 掃描、暴力破解、DDoS、釣魚→C2、勒索軟體、SQL Injection、資料外洩、訪客網路滲透、偽冒 AP；每種都有正確與錯誤的應變行動與事後檢討 |
| 機房管理 | 消防：VESDA 極早期偵煙、預動式灑水、潔淨氣體滅火（火警事件：冒煙 → 起火，損害取決於你的消防設備）；環控：溫濕度、漏水偵測（漏水事件）；空調：精密空調控濕、冷熱通道封閉、送風溫度設定、即時 PUE 與電費 |
| 機房門禁 | 鑰匙鎖 → 感應卡門禁 → 雙因子 + 防尾隨雙門（mantrap）；權限名單（IT 常駐、清潔人員與廠商需陪同、主管不能進入）、權限盤點與門禁紀錄；尾隨進入、清潔人員拔插頭、廠商進場、離職員工卡片未停用等事件 |
| AI 伺服器 | 8-GPU 訓練伺服器（10 kW、液冷）、推論伺服器、400G AI 後端交換器、全快閃 AI 儲存；AI 訓練流量真的跑在網路模擬上，算力利用率 = 供電 × 散熱 × 後端網路 × 儲存 |
| AI 電源櫃 | ORv3 AI 機櫃沒有 PDU：電源櫃（6 × 5.5 kW PSU）決定供電容量、要留 N+1；BBU 掛在 54V 匯流排上撐過發電機啟動前的空窗；PSU 故障、CDU 漏液等事件 |
| 伺服器（實體 / 虛擬 VM） | 虛擬化主機的 vCPU 與記憶體、建立 VM、vMotion 線上遷移、HA 在主機故障時自動重開 VM、N+1 容量、P2V 實體轉虛擬（省機櫃、電費與維護費）；VM 放本機硬碟就不能 HA |
| 專線管理（MPLS / SD-WAN / IPLC） | 台中工廠、高雄營業所、越南廠、東京辦公室各有不同的人數、時區與上班時段；MPLS、IPLC、企業寬頻 + VPN、4G / 5G 備援的延遲、掉包、月租與開通時間；總部的 MPLS 匯接頻寬；SD-WAN 依應用選路（ERP 走專線、上網就近出去）、斷線瞬間切換，傳統路由要等 5 分鐘收斂；國際網路晚上塞車；據點線路中斷、國際海纜中斷事件 |
| 電話語音（交換機） | IP-PBX、向電信業者申請 SIP 中繼（外線路數）、用 Erlang B 規劃阻塞率、SBC 放在 DMZ 對接電信業者、語音 QoS（DSCP EF 優先佇列）、依延遲 / 抖動 / 掉包算出的 MOS 通話品質；客服來電暴增、SIP 盜打國際電話事件 |
| 儲存管理 | 每個部門的資料量與每日成長、NAS / SAN / 擴充櫃 / 主機本機硬碟、RAID 5 / 6 / 10 的可用容量與重建風險、快照、容量預測；硬碟故障、資料暴增事件，空間用完時使用者會來報修 |
| 備份管理 | 備份頻率與保存天數、RPO、備份工作失敗的原因（服務帳號密碼過期、代理程式當掉、憑證過期、備份空間已滿）、3-2-1（磁帶異地保管或雲端備份）、還原演練；誤刪共用資料夾、勒索軟體時到底能不能還原 |
| 用戶端電腦管理 | 一萬台電腦的 Patch Tuesday 與修補合規率、端點管理平台（UEM）自動派送與分批（rings）、內部更新快取（不然一萬台一起下載會塞爆對外頻寬）、BitLocker 與遠端抹除；更新出包、筆電遺失事件 |
| 雲端管理 | Microsoft 365（流量改走網際網路、雲端帳號一定要 MFA）、官網搬上雲端（吸收 DDoS）、雲端備份、Direct Connect 雲端專線、CSPM；儲存桶被設成公開、雲端帳單暴增事件 |

## 封包旅程

拓撲圖上方的「封包旅程」會一步一步追蹤一個封包從員工座位出發的完整路徑：樓層 IDF → 核心交換器 → 防火牆（比對到哪一條規則）→ 路由器（NAT）→ ISP → 網際網路，並標出每一段線路目前的使用率與估計往返延遲。可選的情境包括上網、DNS 查詢、存取檔案伺服器、外部客戶連官網（官網再查資料庫）、訪客 Wi-Fi，以及從網際網路直接連 RDP 的攻擊。

- 封包在拓撲圖上沿著實際路由移動，每一站都有說明（這台設備在做什麼、為什麼這樣轉送）。
- 走不通時會停在出問題的那一站，並說明原因與修正方法（例如沒有對應的防火牆規則、設備故障、線路中斷），按鈕可以直接前往防火牆、機房或採購頁修正。
- 防火牆畫面也有「用封包旅程測試」，改完規則可以馬上驗證。

## 實體接線（機房 → 實體接線）

機房畫面上方切換「機櫃 / **實體接線**」。拓撲圖上的每一條連線，背後都是一條條真實的跳線：插在哪個埠、用什麼光模組、什麼跳線，都看得到也改得了。

- **設備面板**：每台網路設備都有放大的前面板，每個埠都能點——燈號（綠 = 正常轉送、琥珀 = STP 阻擋、紅 = 埠被停用、暗 = 沒有連線、狂閃 = 廣播風暴）、插著的光模組（黑色拉環 = SR 多模、藍色拉環 = LR 單模、灰色 = 電口模組）、跳線顏色（OM4 水藍、OS2 黃、Cat6 藍、DAC 黑）、有沒有貼標籤。
- **埠詳情（show interface）**：介面名稱（Gi / Te / Twe / Hu / FH，伺服器是 eno / ens）、模組、跳線、速率、收發光功率、STP 狀態，不通時會說明原因與修法。
- **動作**：插 / 換 / 拔光模組、從這裡接一條新線（選跳線、兩端模組、LACP、防火牆介面區域，接上去之前就能預覽會不會通）、拔掉一端（另一端還插著、可以拿起來插到別的埠）、翻轉光纖極性、循線追蹤並貼標籤、開關交換器的 STP、設定 LACP。
- **規則（和真實世界一樣）**：兩端模組要成對（SR 對 SR、LR 對 LR、同速率）、跳線要配模組（SR 配 OM4、LR 配 OS2、SR4 / SR8 要 MPO）、埠要支援模組的速率（SFP+ 插不了 25G）、距離不能超過規格、光纖兩端要交叉（極性接反燈就不會亮）；DAC 最長 3～5 m，只能接同一座機櫃。
- **迴圈與 STP**：同一對設備之間多接一條線卻沒有 LACP、同一台交換器兩個埠互接、跨設備的環狀連線，都是迴圈；迴圈上只要有交換器開著 STP，多出來的那條就會被擋下（琥珀燈、不轉送）；全部都沒開就是**廣播風暴**——整個 L2 網域癱瘓，並觸發「廣播風暴」事件。伺服器接兩條線沒有 LACP 時只用一條（另一條待命）。
- **ODF 光纖配線架**：往各樓層的主幹在機房這一端的跳線；拔起來的樓層上行會在這裡顯示「懸空（待接）」。
- 拓撲圖的線路會標出「幾條被 STP 擋下 / 極性接反」等實體狀態，線路詳情列出每一條跳線的兩端埠；設備詳情有「實體接線」按鈕，3D 機房裡點一條跳線也會直接跳到那個埠。
- 拓撲圖的「連線」仍然可以用：那是「請廠商照規格接好」，系統會自動配埠、插上對應的模組與跳線（舊存檔讀進來時也會自動補上）。

## 系統、據點與弱點管理

- **系統**（導覽列的「系統」）：五個分頁。
  - **虛擬化**：叢集的 vCPU / 記憶體用量、每台主機上的 VM、HA 與 N+1 檢查；建立 VM、線上遷移、把 VM 搬到 SAN。實體伺服器的詳情有「轉成 VM（P2V）」。
  - **儲存**：各部門的資料量與成長、每個儲存池的 RAID、使用率與「還能撐幾天」。
  - **備份**：備份頻率、保存天數、快照、磁帶異地保管、雲端備份、3-2-1 檢查、RPO、還原演練與最近的備份工作紀錄。
  - **語音**：電話交換機與 SBC 狀態、同時通話數、外線阻塞率、MOS、Erlang B 外線試算、SIP 中繼申請、語音 QoS、各樓層通話品質。
  - **端點**：修補合規率、下一次 Patch Tuesday、派送方式（使用者自己更新 / UEM 自動派送 / 分批）、更新來源（網際網路或內部快取）、BitLocker。
- **據點**：台灣、越南、日本的地圖，總部、MPLS 骨幹、網際網路與公有雲之間的線路會即時顯示流量與狀態；每個據點可以申請 / 退租線路、切換 SD-WAN 或 VPN，並看到 ERP、檔案、AD 登入、上網各走哪一條路，以及 ERP 的往返延遲。總部卡片管理 MPLS 匯接與雲端專線，雲端卡片管理 Microsoft 365、雲端官網、雲端備份與 CSPM。
- **防火牆 → 弱點管理**：弱點掃描的結果依嚴重度與 SLA 排序，標出對外暴露與已遭利用（KEV）的弱點；可以單台修補，或一鍵排入今晚 02:00 的維護窗口。

## 3D 設備模型

「採購」與「知識庫」裡的設備都有可以 360° 旋轉的 3D 模型，讓你知道實物長什麼樣子、每個零件是做什麼的：

- **在哪裡看**：採購卡片的縮圖（點擊放大）、知識庫卡片上方、事件中開啟的知識卡、設備詳情與樓層 AP 面板的「3D 外觀」按鈕。
- **操作**：拖曳旋轉、滾輪或雙指縮放、雙擊重設；可切換斜角 / 正面 / 背面 / 側面、自動旋轉、零件標示。
- **零件標示**：只標出面向你的零件，例如路由器的 SFP28 / QSFP28 埠與頻外管理埠、防火牆的 HA 同步埠、交換器的 PoE+ 埠與上行埠、伺服器的熱插拔硬碟與備援電源。
- **涵蓋 60 多個模型**：路由器、防火牆、核心 / 匯聚 / 接入交換器、伺服器與儲存、WLC、各型 AP、機架式 UPS、配線架、42U 機櫃（含上架配置）、防火牆 HA 配對、ISP 光纖終端設備、精密空調、模組化 UPS、柴油發電機，以及 Cat6 / Cat6A / OM4 / OS2 線材的剖面與 SFP / QSFP 光模組。
- **AI 與機房設施模型**：8-GPU / 4-GPU AI 伺服器、400G AI 交換器、全快閃 AI 儲存、電源櫃（PSU）、BBU 電池櫃、ORv3 AI 機櫃（背面的 54V 銅排與液冷歧管）、液冷 CDU、VESDA 極早期偵煙、潔淨氣體滅火鋼瓶、環境監控面板與漏水偵測線、冷熱通道封閉。
- **系統設備模型**：虛擬化主機、SAN 全快閃儲存陣列、儲存擴充櫃、LTO 磁帶櫃、IP 電話交換機、SBC 語音邊界控制器、SD-WAN 集中器。

所有模型都是用程式產生（面板圖案以公釐為單位畫在 Canvas 上再貼到立體外殼），不需要下載任何模型檔。

### 3D 機房、3D 大樓剖面、3D 樓層內部

「機房」、「大樓」與「樓層」畫面右上角可以切換 **2D / 3D**（預設 2D，選擇會記在這台瀏覽器）。3D 畫面直接呈現你蓋出來的網路，而且隨遊戲即時變化：

部分知識卡的 3D 區塊附有會動的原理動畫：光纖全反射與模態色散（OM4 vs OS2）、PoE 同時送電與資料、防火牆 HA 主備自動切換、冷熱通道氣流、Wi-Fi 訊號隨距離與牆壁衰減（RSSI 數值與遊戲使用同一套公式）。

## 模擬模型（簡化但保留真實關係）

- **流量**：每層樓依人數、樓層類型（辦公 / 研發 / 客服 / 設計 / 會議 / 主管 / 餐廳）與時段（上班尖峰、午餐串流、夜間備份）產生上網與內部流量；餐廳依早餐、午餐、下午茶、晚餐的用餐人數產生手機流量與收銀機刷卡。
- **路由**：以運作中的設備與線路建圖，最短路徑 + 依容量加權的 ECMP 分流；防火牆 HA 只有 Active 那台轉送，單 WAN 路由器一次只用一條 ISP。
- **壅塞**：每條線路「每個方向」分別計算負載；超過容量就依比例限縮，並產生排隊延遲與封包遺失。路由器 / 防火牆也有處理量上限（開 IPS 會變慢）。
- **Wi-Fi**：1m 格點平面圖，RSSI = 發射功率 − 路徑損耗 − 牆壁衰減；AP 容量考慮距離造成的速率下降、同頻干擾、連線數上限與上行頻寬。
- **滿意度**：可連線比例 × 頻寬滿足率 × 延遲 / 遺失懲罰（客服中心對語音特別敏感）× AD 可用性；電話打不出去、檔案空間滿了、收銀機不能刷卡也會扣分。全公司滿意度依在座人數把四個據點一起算進去。
- **資安**：防火牆規則決定暴露面；各種防護（IPS、EDR、MFA…）改變攻擊成功率與偵測速度；電腦的修補率越低，釣魚與勒索軟體越容易得手。
- **QoS**：開啟語音 QoS 後，語音封包在每一段線路上先分配頻寬、排在優先佇列，其他流量分剩下的頻寬；沒開的話，線路一壅塞電話就跟著掉包。
- **虛擬化**：VM 佔用主機的 vCPU 與記憶體，流量從所在主機的網卡進出；主機故障時，硬碟在 SAN 上的 VM 約 3 分鐘後由 HA 在其他主機重新開機，放本機硬碟的 VM 要等主機修好。N+1 以「壞掉最大的一台之後，剩下的主機放不放得下」計算。
- **儲存與備份**：資料量依部門類型與人數計算、每天成長；RAID 決定可用容量；備份依排程執行、真的佔用網路頻寬，而且可能失敗；RPO = 距離上一次成功備份的時間。勒索軟體事件時，能不能還原取決於有沒有離線、不可變或異地的副本。
- **語音**：通話量依部門與時段計算（客服中心最多），外線阻塞率用 Erlang B，通話品質用 E-model 由延遲、抖動、掉包算出 MOS；每通電話的封包都走網路模擬，外線從電信業者經防火牆（和 SBC）進到電話交換機。
- **廣域網路**：據點的流量（ERP、檔案、AD、上網、電話）都跑在同一張路由圖上；各據點依當地時區上班（越南 −1 小時、東京 +1 小時，工廠有夜班）；傳統架構專線優先、上網也拉回總部再出去，主線斷掉後要約 5 分鐘路由收斂；SD-WAN 依應用選路（ERP、AD、電話走延遲最低的線路，大檔案走網際網路隧道，上網就近出去），線路一斷馬上改走別條；國際網路晚上尖峰會掉包。
- **端點修補**：每週三凌晨 1:00（台灣時間的 Patch Tuesday）發布更新；更新下載真的佔用網路，沒有內部快取時一萬台電腦都從網際網路下載；有一定機率出包，分批派送讓出包只影響試點電腦。
- **弱點**：每週陸續出現新的 CVE，要有弱點掃描才看得見；修補需要重開機，沒有備援的設備會中斷；對外設備（防火牆、路由器、SBC、SD-WAN 集中器、DMZ 的官網）上沒修補的嚴重弱點，每小時都有被入侵的機率（已遭利用的 KEV 更高，IPS 的虛擬修補能擋掉大部分）。
- **機房設施**：一般機櫃由 PDU（8 kW）供電、停電靠 UPS；AI 機櫃由電源櫃供電、停電靠 BBU；發電機約 1 分鐘後接手。溫度 = 空氣熱負載 vs 空調能力（通道封閉 +20%、送風溫度越高越暖），濕度由精密空調控制（太潮濕會結露故障），PUE 依冷卻方式即時計算並反映在電費上。
- **AI 算力**：GPU 伺服器之間的 all-reduce 流量與讀取訓練資料的流量都走網路模擬；後端網路不夠快、儲存太慢、液冷不足（GPU 降頻）或斷電，都會讓算力利用率下降。
- **停車場**：停車場裡的人潮依上下班時段計算（8:30、18:10 兩個尖峰），跟著進駐的員工人數成長；打卡成功率 = 停車格、走道與電梯廳的 Wi-Fi 可用覆蓋 × 能不能連到雲端的人資系統。柵欄機要有交換器埠，監視器要有埠也要有 PoE（每台約 7 W，比 AP 先供電）；打卡失敗、柵欄打不開都會扣滿意度並產生報修。
- **廁所與清潔**：每層樓三間廁所的使用次數 = 在座人數 × 每人每小時約 0.6 次，依男女比例分配；每次使用降低整潔度、衛生紙與洗手乳，偶爾堵塞。白班清潔人員（07:00～22:00）沒有感測器時照固定路線輪流巡，有智慧廁所（而且感測器連得到 IoT 平台）的樓層依需要派工，最急的先去；晚上由夜班清潔公司整理、清晨補滿耗材。廁所很糟最多扣這層樓 10% 的滿意度。清潔人員月薪與耗材每天計入營運成本。
- **機房門禁**：沒有門禁系統時權限設定無法落實（拿到鑰匙就進得去）；清潔人員有常駐權限時，半夜可能拔掉機櫃插頭（整座機櫃斷電，設備要重新開機）；感應卡擋不住尾隨，防尾隨雙門可以；尾隨進來的人沒被處理，會在交換器插上竊聽裝置並外傳資料。
- **實體層**：每條線路由一條或多條跳線組成，容量 = 正常轉送的跳線速率總和；每條跳線依序檢查：埠存在、設備運作中、模組與埠的速率、兩端速率與波長、跳線種類、距離、極性、埠的設定（VLAN）。STP 以 union-find 找出迴圈（L3 核心之間視為 MLAG / 路由互連，同一台設備分別接到兩台核心不算迴圈），多出來的路徑被擋下；迴圈上全部沒開 STP 時，風暴沿著橋接設備擴散，涵蓋到的交換器與樓層全部不轉送。
- **割接（第九章）**：維護窗口內每個實體動作都會真的推進遊戲時間（網路照常模擬）；影響以「離線的樓層人數 × 分鐘」計算，窗口外只算廣播風暴造成的影響；維護窗口內不會發生隨機事件。
- **自己布線**：每層樓依座位與人潮分成最多 8 個配線區；走線長度 = 天花板上的路徑 + 上下 7 m + 區域內最遠的插座（≤ 90 m）；和電力線槽平行 5 m 以上會串音；打線色序錯誤（T568A、接錯）或偶發的打線不良都會讓接線圖 FAIL，要重拉或重新端接後再測。

## 擴充

- **新設備**：在 `js/data/catalog.js` 的 `CAT.devices`（機房）、`CAT.access`（樓層交換器）或 `CAT.aps` 加一筆即可，`unlock` 控制第幾章開放。
- **新事件**：在 `js/data/incidents.js` 的 `G.INC` 加一個物件：`init` / `tick` / `effects` / `actions`（每個行動標上 `good` / `neutral` / `bad` 與說明）。
- **新知識卡**：`js/data/knowledge.js`；要附 3D 模型的話，在 `js/ui/models3d.js` 的 `M3.KB` 對應卡片 id 與模型 id。
- **新原理動畫**：在 `js/ui/anim3d.js` 用 `M3.register(id, fn, { name, cap })` 登錄一個回傳 `{ obj, notes, view, anim(dt, t), caption() }` 的模型，再加進 `M3.KB`。
- **新設備的 3D 模型**：在 `js/ui/models3d.js` 的 `SPEC` 加一筆，用區塊（`ports`、`psu`、`fan`、`drives`、`leds`…）描述前後面板；區塊的 `label` 會自動變成零件標示。
- **新據點**：在 `js/data/sites.js` 的 `G.SITES` 加一筆（人數、各種線路的延遲與掉包、每人的 ERP / 檔案 / 上網 / 電話用量）；與台灣的時差寫在 `js/sim/wan.js` 的 `TZ`，地圖上的位置寫在 `js/ui/view-wan.js` 的 `POS`。
- **新章節或任務**：`js/data/campaign.js`，任務的 `check` 是一個回傳 true / false 的函式；`sustain` 代表要持續多少遊戲分鐘。
- **新任務的提示**：在 `js/data/hints.js` 用任務 id 加一個回傳步驟陣列的函式；每一步 `{ text, short, go, path, done }`，`path` 是由粗到細的 `data-hint` 名稱（例如 `nav:shop` → `tab:shop:net` → `buy:NR-1100`），畫面上找得到的最細那一個會被標出來。要被提示的按鈕加上 `data-hint` 屬性即可。
- **新測驗題**：`js/data/quiz.js`，每題 `{ q, o, why, kb }`，`o` 的第一個選項是正確答案（顯示時會打亂）。
- **新情境挑戰**：在 `js/data/scenarios.js` 的 `Scen.list` 加一個物件：`setup`（用 `buildNetwork` 建網、撥時間、排事件）、`begin` / `pre` / `post`（每分鐘調整流量與取樣）、`live`（任務面板數據）、`score`（回傳分數與檢討）。

所有模組都掛在全域物件 `G` 底下（沒有使用 ES module），所以直接用 `file://` 開啟也能執行。
