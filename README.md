# 萬人網管 InfraOps

一款 **IT 基礎架構工程師模擬遊戲**：新曜集團的一萬名員工即將遷入 21 層的新總部，而你手上只有一間空蕩蕩的 B1 機房。從機櫃、路由器、防火牆、核心交換器，到每層樓的布線、Wi-Fi、跨樓層光纖主幹，親手打造整間公司的網路，並在流量高峰、設備故障與駭客攻擊中守住它。

純 HTML / CSS / JavaScript，**不需要安裝任何東西**。（3D 設備模型使用 [Three.js](https://threejs.org/) r128，第一次打開 3D 畫面時才從 cdnjs 載入，需要網路連線；離線時其他功能照常運作。）

**▶ 線上遊玩：https://sksksk1748.github.io/IT_Infra_Sim/**

## 怎麼玩

### 直接開啟
雙擊 `index.html`，用 Chrome / Edge / Firefox 開啟即可。

### 本機伺服器（選用）
這台電腦沒有 Node / Python 也沒關係，專案附了一個 PowerShell 小伺服器：

```bash
powershell -ExecutionPolicy Bypass -File tools/serve.ps1 -Port 8080
```

然後打開 http://localhost:8080/ 。

### 遊戲模式
- **劇情模式**：五個章節，任務面板會一步步引導你。
- **沙盒模式**：預算 1.5 億、全部設備解鎖，員工在第 3～6 天分批進駐全部樓層，隨機事件照常發生。
- **情境挑戰**：開始畫面的「情境挑戰」。每個情境都會先蓋好一套公司網路（刻意留一些弱點），把時間撥到事發前，限時處理完畢後依結果評分（S / A / B / C / D）並給出檢討，最佳成績記在這台瀏覽器：
  - **凌晨 3 點：勒索軟體**（困難）：6F 爆發勒索軟體，09:00 上班前完成遏制、根除、復原。
  - **季末流量高峰**（中等）：找出路由器、防火牆、專線哪個是瓶頸，預算內升級，撐過 3 小時的 1.6 倍流量。
  - **官網上線日：DDoS**（中等）：發表會流量 3 倍、DDoS 與 SQL Injection 接連來襲；容量規劃、上游清洗、WAF 缺一不可。
- **章節小測驗**：每章 5 題選擇題（知識庫右上角「章節小測驗」，或完成章節時直接開始）。答錯會附上解說與相關知識卡，劇情模式只開放已經玩到的章節。

### 操作
- 上方 `❚❚ 1× 5× 20× 60×` 控制時間，`⏭` 快轉到早上；鍵盤 `0`～`4` 切換速度、空白鍵暫停 / 繼續。
- 左側（手機在下方）是一排「交換器連接埠」導覽，亮琥珀燈代表那裡有事情需要處理。
- 進度每遊戲小時自動存在瀏覽器；「選單」可以匯出 / 匯入存檔文字。
- **淺色 / 深色背景**：右上角的 ☀ / ☾ 按鈕可以一鍵切換；「選單 → 畫面外觀」與開始畫面可選「跟隨系統 / 淺色 / 深色」，選擇會記在這個瀏覽器（手機版請從選單切換）。

| 章節 | 情境 | 學習重點 |
|---|---|---|
| 一、B1 機房開張 | 週末內讓 2F 的 527 人週一能上網 | 機櫃與 U 數、ISP 專線、路由器 / 防火牆 / 交換器的角色、DHCP / DNS / AD、水平布線、AP、防火牆預設拒絕 |
| 二、大遷徙 | 3F～8F 三天內進駐 3,600 人 | 檔案伺服器與內部流量、NMS 監控、ISP 頻寬規劃、PoE 預算、頻道規劃與 WLC、IP 子網路 |
| 三、開門迎客 | 官網上線、大廳開放訪客 | 外網 / DMZ / 內網、NAT、訪客網路隔離、VLAN、最小權限規則、IPS / WAF |
| 四、萬人進駐 | 13 層樓、6,000 人一週內搬進來 | 光纖距離（17F 以上超過 100m）、雙核心雙上行、防火牆 HA、雙 ISP、UPS + 發電機、N+1 冷卻 |
| 五、資安風暴 | 勒索集團三天內發動連續攻擊 | 縱深防禦、SIEM、EDR / MFA / 郵件安全 / NAC、內部網段分割、不可變備份、事件應變流程 |

## 遊戲中對應的真實概念

| 你要求的主題 | 在遊戲中怎麼體驗 |
|---|---|
| Router | 路由效能上限、NAT、單 WAN（主備援）vs BGP（多 ISP 負載分擔） |
| Switch | L2 / L3、埠數與埠速（RJ45 / SFP / QSFP）、接入交換器 PoE 預算、核心埠數用完 |
| Server | 角色（AD、檔案、DB、官網、NMS、SIEM、備份）、網卡速率、放在哪個區域 |
| Rack 架設 | 42U 機櫃逐 U 上架、每櫃 8 kW PDU 上限（超過會跳脫）、UPS、精密空調、機房溫度 |
| 樓層間布線 | 每層樓的水平布線工程、經弱電豎井到 B1 的主幹線；Cat6 / Cat6A / OM4 / OS2 的距離與速率限制、光模組成本、LACP |
| Wi-Fi 與有線 | 平面圖上放 AP、牆壁與電梯井衰減、覆蓋 vs 容量、同頻干擾、WLC 自動頻道；有線座位的埠數 |
| 外網與內網 | 防火牆介面區域（OUTSIDE / INSIDE / DMZ）、依實際接線判定安全區域、繞過防火牆會被健檢抓出來 |
| 流量即時監控 | 監控中心：WAN / 內部流量趨勢、鏈路使用率排行、NetFlow 異常流量、告警；沒有 NMS 就看不到 |
| 防火牆 | 由上而下比對的規則表、預設拒絕、命中數、遮蔽規則偵測、業務必要連線檢查、資安健檢評分 |
| 駭客攻擊 | 掃描、暴力破解、DDoS、釣魚→C2、勒索軟體、SQL Injection、資料外洩、訪客網路滲透、偽冒 AP；每種都有正確與錯誤的應變行動與事後檢討 |

## 封包旅程

拓撲圖上方的「封包旅程」會一步一步追蹤一個封包從員工座位出發的完整路徑：樓層 IDF → 核心交換器 → 防火牆（比對到哪一條規則）→ 路由器（NAT）→ ISP → 網際網路，並標出每一段線路目前的使用率與估計往返延遲。可選的情境包括上網、DNS 查詢、存取檔案伺服器、外部客戶連官網（官網再查資料庫）、訪客 Wi-Fi，以及從網際網路直接連 RDP 的攻擊。

- 封包在拓撲圖上沿著實際路由移動，每一站都有說明（這台設備在做什麼、為什麼這樣轉送）。
- 走不通時會停在出問題的那一站，並說明原因與修正方法（例如沒有對應的防火牆規則、設備故障、線路中斷），按鈕可以直接前往防火牆、機房或採購頁修正。
- 防火牆畫面也有「用封包旅程測試」，改完規則可以馬上驗證。

## 3D 設備模型

「採購」與「知識庫」裡的設備都有可以 360° 旋轉的 3D 模型，讓你知道實物長什麼樣子、每個零件是做什麼的：

- **在哪裡看**：採購卡片的縮圖（點擊放大）、知識庫卡片上方、事件中開啟的知識卡、設備詳情與樓層 AP 面板的「3D 外觀」按鈕。
- **操作**：拖曳旋轉、滾輪或雙指縮放、雙擊重設；可切換斜角 / 正面 / 背面 / 側面、自動旋轉、零件標示。
- **零件標示**：只標出面向你的零件，例如路由器的 SFP28 / QSFP28 埠與頻外管理埠、防火牆的 HA 同步埠、交換器的 PoE+ 埠與上行埠、伺服器的熱插拔硬碟與備援電源。
- **涵蓋 40 個模型**：路由器、防火牆、核心 / 匯聚 / 接入交換器、伺服器與儲存、WLC、各型 AP、機架式 UPS、配線架、42U 機櫃（含上架配置）、防火牆 HA 配對、ISP 光纖終端設備、精密空調、模組化 UPS、柴油發電機，以及 Cat6 / Cat6A / OM4 / OS2 線材的剖面與 SFP / QSFP 光模組。

所有模型都是用程式產生（面板圖案以公釐為單位畫在 Canvas 上再貼到立體外殼），不需要下載任何模型檔。

### 3D 機房、3D 大樓剖面、3D 樓層內部

「機房」、「大樓」與「樓層」畫面右上角可以切換 **2D / 3D**（預設 2D，選擇會記在這台瀏覽器）。3D 畫面直接呈現你蓋出來的網路，而且隨遊戲即時變化：

- **3D 機房**：機櫃與設備依實際上架位置擺放；狀態燈（綠 = 運作、黃閃 = 開機、紅閃 = 故障、熄滅 = 斷電）、每座機櫃的用電與斷路器跳脫、精密空調與 UPS；冷通道的藍色冷風與熱通道的紅色熱風會隨冷卻能力與機房溫度改變。
  - **接線**：拓撲圖上的每一條線都會出現在機房裡 —— 同一座機櫃內的跳線、走機櫃上方線槽的跨櫃線路、從後牆弱電豎井往各樓層的主幹線、從左牆進來的 ISP 專線；依線材上色，光點代表流量，滿載變橘、中斷變紅。
  - **事件臨場感**：設備故障冒煙、機房過熱時出現熱浪、停電改由 UPS 供電時琥珀色警示燈閃爍。
  - 點設備看詳情、點兩下拉近；在倉庫選好設備後，點機櫃中亮起的空位就能直接上架。
- **3D 大樓剖面**：21 層樓 + B1 機房的剖面。窗戶亮燈 = 現在真的在座的人（上班時間多、半夜只剩客服夜班）、顏色 = 滿意度；右前角的弱電豎井裡是各樓層連回 B1 核心的主幹線，依線材上色（Cat6A / OM4 / OS2），線上移動的光點代表流量（越密越滿）；網際網路經由 ISP 專線進入 B1。
  - **日夜變化**：天空顏色、太陽 / 月亮與星星、燈光亮度跟著遊戲時間變化。
  - **事件臨場感**：光纖被挖斷的位置冒火花、ISP 中斷時人孔冒火花、停電時窗戶熄燈且戶外發電機啟動冒排氣、沒有 UPS 的 IDF 斷電熄燈、機房過熱時出現熱浪。
  - 點樓層顯示資訊卡，可以進入樓層規劃或「走進樓層（3D）」，點兩下拉近。
- **3D 樓層內部**：依平面圖自動產生隔間牆（玻璃 / 石膏板 / 加厚牆，衰減不同）、核心筒與 IDF 弱電室、開放式座位、會議室與教室、主管室、實驗室、茶水間；座位上的人數跟著目前在座人數變化，有人的電腦螢幕會亮。
  - 天花板上的 AP 會發出訊號波紋，燈號代表負載；AP 到 IDF 的水平布線、IDF 經豎井往 B1 的主幹線都看得到，光點代表流量。
  - 地板的彩色覆蓋層和 2D 平面圖相同：訊號強度、AP 負載、同頻干擾（相同顏色 = 相同頻道，紅線 = 互相干擾）。滑過地板可以看到那個位置的訊號強度與服務它的 AP；選「放置 AP」後點地板就能安裝。
  - 資安事件也會出現在樓層裡：勒索軟體加密中的電腦螢幕變紅、偽冒基地台閃紅光；整層斷線時螢幕變橘色並顯示警示。
- **駭客攻擊路徑**：已偵測到的資安事件會在大樓剖面上以紅色光點沿著模擬中實際的路由移動（例如 DDoS 塞滿 ISP 線路、受感染樓層連往 C2、橫向掃描檔案伺服器），被防火牆擋下的攻擊在擋下的位置顯示綠圈；遭釣魚或勒索的樓層窗戶會閃紅。

### 知識庫原理動畫

部分知識卡的 3D 區塊附有會動的原理動畫：光纖全反射與模態色散（OM4 vs OS2）、PoE 同時送電與資料、防火牆 HA 主備自動切換、冷熱通道氣流、Wi-Fi 訊號隨距離與牆壁衰減（RSSI 數值與遊戲使用同一套公式）。

## 模擬模型（簡化但保留真實關係）

- **流量**：每層樓依人數、樓層類型（辦公 / 研發 / 客服 / 設計 / 會議 / 主管）與時段（上班尖峰、午餐串流、夜間備份）產生上網與內部流量。
- **路由**：以運作中的設備與線路建圖，最短路徑 + 依容量加權的 ECMP 分流；防火牆 HA 只有 Active 那台轉送，單 WAN 路由器一次只用一條 ISP。
- **壅塞**：每條線路「每個方向」分別計算負載；超過容量就依比例限縮，並產生排隊延遲與封包遺失。路由器 / 防火牆也有處理量上限（開 IPS 會變慢）。
- **Wi-Fi**：1m 格點平面圖，RSSI = 發射功率 − 路徑損耗 − 牆壁衰減；AP 容量考慮距離造成的速率下降、同頻干擾、連線數上限與上行頻寬。
- **滿意度**：可連線比例 × 頻寬滿足率 × 延遲 / 遺失懲罰（客服中心對語音特別敏感）× AD 可用性。
- **資安**：防火牆規則決定暴露面；各種防護（IPS、EDR、MFA…）改變攻擊成功率與偵測速度。

## 擴充

- **新設備**：在 `js/data/catalog.js` 的 `CAT.devices`（機房）、`CAT.access`（樓層交換器）或 `CAT.aps` 加一筆即可，`unlock` 控制第幾章開放。
- **新事件**：在 `js/data/incidents.js` 的 `G.INC` 加一個物件：`init` / `tick` / `effects` / `actions`（每個行動標上 `good` / `neutral` / `bad` 與說明）。
- **新知識卡**：`js/data/knowledge.js`；要附 3D 模型的話，在 `js/ui/models3d.js` 的 `M3.KB` 對應卡片 id 與模型 id。
- **新原理動畫**：在 `js/ui/anim3d.js` 用 `M3.register(id, fn, { name, cap })` 登錄一個回傳 `{ obj, notes, view, anim(dt, t), caption() }` 的模型，再加進 `M3.KB`。
- **新設備的 3D 模型**：在 `js/ui/models3d.js` 的 `SPEC` 加一筆，用區塊（`ports`、`psu`、`fan`、`drives`、`leds`…）描述前後面板；區塊的 `label` 會自動變成零件標示。
- **新章節或任務**：`js/data/campaign.js`，任務的 `check` 是一個回傳 true / false 的函式；`sustain` 代表要持續多少遊戲分鐘。
- **新測驗題**：`js/data/quiz.js`，每題 `{ q, o, why, kb }`，`o` 的第一個選項是正確答案（顯示時會打亂）。
- **新情境挑戰**：在 `js/data/scenarios.js` 的 `Scen.list` 加一個物件：`setup`（用 `buildNetwork` 建網、撥時間、排事件）、`begin` / `pre` / `post`（每分鐘調整流量與取樣）、`live`（任務面板數據）、`score`（回傳分數與檢討）。

所有模組都掛在全域物件 `G` 底下（沒有使用 ES module），所以直接用 `file://` 開啟也能執行。
